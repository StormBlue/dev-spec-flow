# 单任务自检清单

每个任务实现完，commit 之前都要走一遍这个清单。**自检不是形式主义**，是发现问题最便宜的窗口（自己改 vs. 后面 review 让用户发现 vs. 上线后修，成本指数级递增）。

---

## 五项必检

### ① 功能是否完整？

- **拿这个任务对应的 Requirement / Scenario 逐条对照**（任务在 `tasks.md` 里标了它实现哪条 Requirement）——每个 `#### Scenario` 的 WHEN/THEN 都满足了吗？
- 对应的自动化测试写了且通过了吗？（测试深度见 `verification.md`）
- "成功路径" 走通了吗？（真跑一遍，不只是看代码）
- "失败路径" 处理了吗？（错误信息友好、不崩、不丢数据）

**问自己**：如果我现在交给用户，他会不会立刻找到一个 "这个不行" 的点？

### ② 逻辑是否有漏洞 / 边界情况？

逐项过：

- **空 / null / undefined / 0 / 空字符串 / 空数组 / 空对象** —— 每个用户输入和外部数据都要想：如果它是这些会怎样？
- **极值 / 溢出** —— 数字超大、字符串超长、列表超多。
- **并发 / 竞态** —— 多人同时改、多请求同时来、同一用户连点。
- **网络 / IO 故障** —— 网络断、超时、第三方挂、磁盘满。
- **权限 / 鉴权** —— 未登录、登录但无权限、token 过期。
- **国际化** —— 时区、语言、字符集、RTL。
- **历史数据** —— 老用户的旧数据格式还能读吗？migration 写了吗？

### ③ 是否引入 bug？

- 跑现有测试套件，确保没挂掉（如果项目有测试）。
- 跑 lint / type check（`tsc --noEmit`、`pyright`、`mypy`、`cargo check`、`go vet` 等）。
- 改动的地方手动跑一遍。
- 改动有没有不小心碰到无关代码？diff 干净吗？

### ④ 类型是否安全？

- 没有 `any`、`unknown`（除非有充分理由 + 注释）
- 公开函数都有显式签名
- 联合类型、可选字段、null 都正确建模
- 类型断言（`as`、`#[allow(...)]`）有理由

### ⑤ 注释是否充足？

按 `dev-rules.md` 规则 4：

- 反直觉的代码有解释
- 隐含约束写下来
- 决策理由写下来
- 没有冗余注释

---

## UI / 前端额外检查

如果任务涉及界面：

- **响应式**：手机 / 平板 / 桌面三档至少都看一眼
- **加载态 / 空态 / 错误态**：都有像样的展示？
- **可访问性**：键盘可达、screen reader 可读、对比度够、focus 可见
- **国际化**：长文本不溢出、RTL 不破

---

## 数据层额外检查

如果任务涉及数据库 / 持久化：

- **migration 可逆**（写了 down / rollback）
- **索引**：新增的查询路径有没有走索引？
- **事务**：跨表写有事务包吗？
- **删除**：硬删 vs 软删，业务真的要硬删吗？
- **备份**：会不会一行 SQL 把表删了？

---

## 安全层额外检查

如果任务涉及输入处理 / 鉴权 / 数据流出：

- **注入**：SQL 用参数化、shell 用 escape、HTML 用 escape、路径用 normalize
- **鉴权检查**：每个 endpoint 都鉴权了？还是有的漏？
- **敏感数据**：日志里没打印 token / 密码 / PII？
- **依赖**：新加的包有 CVE 吗？

---

## 自检后填备注块

按 `tasks.md` 模板，往任务下的备注块填：

- 🐛 **遇到的问题**：实际开发中卡了哪些点？怎么解的？（这是给未来自己 / 用户 / 接手人的礼物）
- 🔧 **最终实现逻辑**：跟原计划有什么不一样？为什么？关键函数 / 文件在哪？
- 🎯 **关键决策**：选了 A 而不是 B 的理由

**写不出来 = 没想清楚**。如果备注块空着，说明你没真的吃透这个任务，重新审一遍。
