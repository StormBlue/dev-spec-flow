# REQ-2026-001: Upgrade dev-spec-flow to a risk-driven lifecycle

## Why

The current workflow equates acceptance scenarios with new automated tests, fixes review volume to change size, retains every review report, and treats archive as an optional final step. Its copied platform instructions also drift, and change records lack reliable chronology.

## Outcome

Provide one platform-neutral Skill that routes composable actions by uncertainty and risk, uses heterogeneous evidence, performs focused review, and closes changes through a deterministic, recoverable archive operation. Integrate with docs-architect through shared artifact identities instead of duplicated requirement and plan trees.

## Scope

### In scope

- Canonical Skill and detailed reference policy.
- Stable lifecycle metadata, artifact templates, evidence and retention rules.
- Standard-library CLI for change creation, status, validation, verification, close, install, update, and doctor.
- Thin platform adapters and safe hash-based installation updates.
- Automated tests, self-validation, README migration guidance, and dogfood close.

### Out of scope

- Modifying the separate docs-architect repository in this change.
- Claiming unverified Grok installation locations or advanced agent capabilities.
- Migrating timestamps for third-party repositories without evidence.

## Acceptance Criteria

- [x] `AC-1` - Canonical actions and dual-axis policy are implemented.
- [x] `AC-2` - Evidence methods replace automatic Scenario-to-test mapping.
- [x] `AC-3` - Review and report retention are risk-driven.
- [x] `AC-4` - Stable IDs, timestamps, and chronological status are implemented.
- [x] `AC-5` - Close is dry-runnable, idempotent, and safely archives.
- [x] `AC-6` - docs-architect ownership and handshake are explicit.
- [x] `AC-7` - Four-platform packaging uses one canonical Skill and safe updates.
- [x] `AC-8` - Automated verification covers the new behavior.
- [x] `AC-9` - Final commit is pushed to `origin/develop`.

## Documentation Impact

The Skill itself is durable workflow documentation. `SKILL.md`, `README.md`, references, templates, and platform adapters must be synchronized as part of this requirement.
